# GreenZone · 신월1동

**신월1동의 건물을 검색하면 팀이 분석한 담당 생활권과 그린존 거점안을 지도에서 확인하는 웹입니다.** 모든 위치는 운영 승인 전 분석 제안입니다.

## 현재 구현과 데이터

| 구분 | 내용 |
|---|---|
| 현재 데이터 | 주거 1,585필지 · 등록 주거단위 7,193 · 생활권 9개 · 거점안 9곳 |
| 건물 검색 | 보유 도로명주소·지번·건물명 검색 → 10개씩 더보기 → 선택 → 담당 생활권·거점 표시 |
| 지도 | 검색/후보지 탭 분리, 카카오 지도·클릭 주소 확인, 생활권·표시 체크 |
| 분석 설명 | 받은 엑셀의 보행거리 비교, 후보 도로폭·보호시설 이격, 출처 다운로드 |
| 분석 보기 | Leaflet / Folium 보기, 6곳/9곳 비교·도로 등록폭·보호시설 200m 반경 표시 필터 |
| 수거 경로안 | 선택 거점·출발 거점·복귀 조건 → 도로 최단거리와 최근접 방문 순서 → 지도 표시 |
| 배출량 | 2024 결합권역 공식값과 과거 조건부 추정을 구분해 참고 표시 |

**9곳 = 기존 1차 후보 6곳 + 새 대안 3곳**입니다. 11곳을 도로폭으로 걸러 9곳이 남았다는 뜻은 아닙니다.
7,193은 건축물대장 기반 등록 주거단위이며 실제 거주 인구나 관측 배출량이 아닙니다.

## 실행

아래 명령은 프로젝트 폴더에서 실행합니다. 처음 받은 팀원은 가상환경과 `.env`를 준비합니다.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

1. [Kakao Developers](https://developers.kakao.com/)에서 앱의 **JavaScript 키**를 확인합니다.
2. 카카오맵 사용 설정을 확인하고, 허용 웹 도메인에 `http://localhost:8000`을 등록합니다. 팀원도 각자 사용하는 키의 앱에 같은 주소를 등록합니다.
3. `.env`의 `KAKAO_JAVASCRIPT_KEY=` 뒤에 키를 입력합니다. Java 키·REST API 키를 넣는 칸이 아닙니다.
4. 아래 명령으로 서버를 켜고 [http://localhost:8000/](http://localhost:8000/)을 엽니다.

```powershell
.venv\Scripts\python.exe -m uvicorn main:app --host localhost --port 8000 --reload --no-access-log
```

Docker·Ollama는 현재 구현 실행에 필요하지 않습니다. 지도는 카카오 SDK, 검색창은 보유 데이터에서 처리합니다. 팀의 지도 클릭 주소 표시는 같은 키의 카카오 좌표→주소 기능으로 연결했습니다.
직접 설치할 패키지는 `fastapi`, `uvicorn`, `python-dotenv`, `jinja2`, `folium==0.20.0`입니다. Folium은 Python으로 보고용 HTML 지도를 만들기 위해 추가했으며 관련 의존성은 함께 설치됩니다. 기존 환경도 `pip install -r requirements.txt`로 갱신합니다.
`.env`는 각자 작성하고 공유·커밋하지 않습니다. 데이터 파일을 교체했다면 서버를 다시 시작합니다.
**접속 주소도 `localhost:8000`으로 맞춥니다.** `127.0.0.1:8000`은 카카오의 허용 웹 도메인과 별도 주소입니다. 기존 8003 서버를 터미널에서 실행 중이면 `Ctrl+C`로 멈추고 위 명령을 실행합니다.
`.gitattributes`는 data 파일의 줄바꿈 변환을 막아 팀원 PC에서도 원본 SHA256이 유지되게 합니다.

## 현재 범위의 한계

생활권·보호시설 체크는 표시 필터이며 팀의 수요·생활권 분석을 재실행하지 않습니다. 경로안 계산 버튼은 선택 거점과 도로폭 조건에 따라 별도로 계산합니다. 개별 집의 실제 보행거리·차량 운행 검증·위성보기·LLM/RAG는 포함하지 않았습니다.
도로 분석 결과는 있으나 원본 SHP·표제부·중간 거리행렬을 모두 받아 재현한 상태는 아닙니다. 현장 유효폭·정차·보행 안전·부지 사용 동의는 별도 확인이 필요합니다.
이전 6,853 비교 그림은 `data/received/archive/`, 현재 웹은 7,193·9생활권 결과를 사용합니다.

## 분석 보기와 수거 경로안

첫 화면 위쪽에 **Leaflet 보기 / Folium 보기** 버튼을 나란히 두었습니다. 두 화면 상단에서도 서로 전환합니다. 같은 팀 자료와 비교표를 사용하며 마커·도로 클릭으로 받은 값을 확인합니다.

- **Leaflet 보기** (`/analysis`): 화면에서 체크·생활권·도로폭을 바꾸면 바로 표시를 바꿉니다.
- **Folium 보기** (`/analysis/folium`): 6곳/9곳·도로폭을 고르고 `조건 적용 · 지도 만들기`를 누르면 Python이 HTML 지도를 만듭니다. 지도 오른쪽 위 체크 목록에서 필지·도로·보호시설 등을 겹쳐 봅니다. 조건을 적용하면 지도 체크·확대는 초기화됩니다.

두 분석 화면은 표시 필터이며 후보 재선정·경로 계산을 호출하지 않습니다. Folium 패키지만 추가했으며 별도 API 키는 없습니다. 지도 도구와 OpenStreetMap 배경을 불러오려면 인터넷 연결이 필요합니다.

생활권·필지는 같은 9가지 색으로 구분합니다. 기존 거점은 초록 원, 새 대안은 주황 사각형, 도로는 진한 파랑, 보호시설 반경은 빨간 점선입니다. 아래의 번호 범례와 함께 읽습니다. 두 화면의 공통 생활권 색은 `folium_report.py`의 `ZONE_COLORS`에서 관리합니다.

후보지 목록 탭에서 **6곳/9곳·도로폭·도로선·보호시설 반경**을 고르고, `수거 순회 경로안 만들기`를 펼칩니다. 거점을 체크하고 출발 거점·복귀 여부를 고른 뒤 `경로안 계산`을 누릅니다. 주황 실선은 도로 경로, 회색 점선은 현장 확인이 필요한 거점↔도로 관계선입니다.

- 계산은 **구간 최단거리(다익스트라) → 가까운 미방문 거점 선택**입니다. 전체 최적 경로를 보장하지 않습니다.
- 입력은 받은 팀 도로 162구간과 현재 거점 9곳입니다. 팀 2차의 3.22km를 재현한 값과 구분합니다.
- 도로는 양방향으로 가정합니다. 일방통행·회전 제한·입체교차·차고지·정차·부지 진입은 미검증입니다. 도로 접속거리는 운행거리에서 제외하며, 연결 불가 시 사유를 표시합니다.
- 경로안은 현재 카카오 지도에 연결했습니다. 별도의 Leaflet/Folium 분석 보기와 구분합니다.

코드는 `static/route.js → main.py의 @app.get('/api/route') → route_planner.py` 순서로 읽습니다. 함수·데코레이터 설명은 코드 옆 주석과 [핸드북](docs/HANDBOOK.md#11-분석-필터와-수거-경로안)에 있습니다.
