# 양천구 평가셋 v1 검토와 결과 분석 기준

검토일: 2026-10-22 · 대상: 사용자가 제공한 `yangcheon_eval_v1.zip` · 상태: **평가 준비 검토, 모델 실행 결과 아님**

## 1. 사용 결정

이 묶음은 사진·질문·정답 기준을 갖춘 **비공개 평가용 입력**으로 사용한다. 원본 ZIP·사진·원본 XLSX는 팀 저장소에 복사하지 않는다. 원본은 사용자의 Downloads에 보관한다. 팀에 공유하는 것은 개인정보를 제외한 검토 내용과, 이후 실제 실행에서 얻은 평가 집계·실패 유형이다.

이번 작업은 압축 안의 엑셀·이미지 메타데이터를 로컬에서 읽은 것이다. 모델/API 호출·Opik 업로드·원본 이미지 전송은 수행하지 않았다. 개인정보가 들어간 픽셀·문서 속성까지 모두 비식별화됐다고 판정하지 않았다.

## 2. 들어 있는 자료

| 항목 | 확인 내용 | 평가에서의 역할 |
|---|---|---|
| `questions.xlsx` | 질문 10건, 품목·기대 행동·기대 답변·필수/금지 요소 | 평가 케이스 |
| `sources.xlsx` | 수수료 43행, 스마트클린 양천 출처와 **2026-10-22 출처기준일** | 제공자가 정리한 정답 근거 스냅샷 |
| `evaluate.xlsx` | 예시 답변·PASS/FAIL 2행, 실제 입력용 질문10행 | 결과 입력 서식. 예시 2행은 성능 집계 제외 |
| 사진 | 가구 사진 7장 | 사진 후보 평가 입력 |

43행은 밥상 3, 서랍장 16, 소파 3, 장롱 5, 침대 14, 특수 침대 2행이다. 총 다섯 시연 품목군에 대응한다. 파일의 “출처기준일”은 제공자의 스냅샷 기준이며 법령 시행일이나 각 자료의 독립 검수 완료일을 뜻하지 않는다.

실제 평가 답변이 채워진 행은 현재 **0건**이다. 따라서 정확도·통과율·환각률은 아직 산출할 수 없다. 예시 1 PASS·1 FAIL을 50%로 집계하지 않는다. 입력용 질문 ID에는 탭 공백이 있어 실제 평가 처리 때 공백을 제거해야 한다.

## 3. 개인정보 취급

7장 중 **3장에 GPS EXIF가 존재**한다. 위치 좌표·촬영 시각·원본 메타데이터 값은 이 문서와 Git에 기록하지 않는다. 나머지 사진에 EXIF가 없다는 사실도 사진 배경·문자·얼굴의 개인정보 부재를 보장하지 않는다.

외부 Vision API에 평가 사진을 보내기 전에는 별도 작업 복사본에서 EXIF를 제거하고 픽셀 속 얼굴·번호판·주소·이름·문서 등이 있는지 사람이 확인해야 한다. 원본 사진의 이용·전송 권한도 확인한다. 현재 서비스의 전송 전 EXIF 제거 기능만으로 원본 사진 전체의 공개 가능성을 판정하지 않는다.

공유 결과에는 **평가셋 ID·질문 ID·모델/버전·설정·근거 ID·판정·실패 유형·처리시간·측정된 사용량** 정도를 남긴다. 원본 사진, GPS, 질문에 포함된 개인정보, 키·비밀번호, 개인정보가 포함될 수 있는 원문 모델 답변은 그대로 Git·Opik에 올리지 않는다. 원문 답변은 로컬에서 검토한 뒤 필요하면 비식별 요약만 공개한다.

## 4. 기존 공식표 스냅샷과의 대조

기존 프로젝트의 `data/knowledge/waste_catalog.json`(2026-10-18 확인 스냅샷)과 제공된 43행을 비교했다.

- 37행은 같은 품목·공백을 정리한 규격·금액이 일치했다.
- 6행은 제공본의 `밥상` ↔ 기존 `밥상(교자상)`, `소파` ↔ 기존 `소파(안락의자)`라는 명칭 차이가 있다. 이 대응을 적용하면 제공본의 규격·금액과 일치한다.
- **기존 스냅샷에는 소파 4인용 행도 있지만 제공본은 3인용까지만 담고 있다.** 제공본 43행의 값이 기존 값과 일치해도 전체 규격이 완전하다는 뜻은 아니다.

이것은 두 스냅샷의 로컬 대조 결과다. 현행 공식 전체 목록의 완전성과 최신 금액을 확인한 결과가 아니다. 공식 페이지는 동적 품목 목록이라 이번 웹 본문 조회에서 개별 행이 추출되지 않았다. [공식 수수료 페이지](https://smartclean.yangcheon.go.kr/online/bulky/item)는 목록 외 품목에 유사 수수료를 적용한다는 일반 안내도 제공하므로, 부분표의 행 부재만으로 공식 규정 전체의 부재를 단정하지 않는다.

## 5. 질문별 채점 전 검토

질문 ID 충돌을 피하기 위해 이 묶음은 `yangcheon_v1:Q01`처럼 평가셋 ID를 붙인다. 기존 계획 문서의 Q01~Q10과 질문 내용이 다르므로 같은 질문으로 합치지 않는다.

| 케이스 | 목표 | 채점 전 확인할 점 |
|---|---|---|
| Q01 | 소파 규격 확인·금액 안내 | 규격을 모르면 질문을 하는 응답도 정답으로 인정. 모든 가격을 열거해야만 통과시키지 않음 |
| Q02 | **의도적 자료 충돌·오류 탐지** | 제공 부분표와 기존 DB의 4인용 규격 유무를 대조. 충돌·버전 차이를 밝히고 확인/보류하거나, 현재 공식 근거를 실제 확인한 경우 그 출처로 설명. 목록 일부만 보고 전체 규정 부재를 단정하면 실패 |
| Q03 | 침대의 구성품·인용 확인 | 매트리스·프레임 및 세트 규칙이 함께 존재. 선택 가능한 공식 세트 안내도 인정. 헤드가 실제 배출 대상일 때 추가 안내 |
| Q04 | 두께·인용이 주어진 매트리스 | **Q03의 후속 질문.** 앞선 품목 맥락과 새 조건을 함께 전달. 사진만으로 두께 측정했다고 평가하지 않음 |
| Q05 | 장롱 폭 확인 | 사진으로 폭을 확정하지 않음. 숫자 구간은 공식 표 표현을 그대로 사용 |
| Q06 | 150cm 장롱의 추가 확인 | **Q05 후속 질문.** 제공된 부분표 밖이라는 점과 공식 전체 규정 부재를 구분 |
| Q07 | 밥상 품목 인식 | 사진의 독립 육안 정답 확인이 필요. 원본 파일명이나 저장 폴더를 모델 정답의 근거로 삼지 않음 |
| Q08 | 5인용 밥상의 불명확한 구간 | 부분표에 딱 맞는 행이 없다는 이유로 금액을 임의 보간하지 않음. 공식 유사 품목 적용·문의 안내를 대조 |
| Q09 | 서랍장/수납장 혼동 수정 | 사용자의 주장에 무조건 동의하는 응답을 정답으로 삼지 않음. 독립 사진 확인·공식 품목 선택·규격 요청을 평가 |
| Q10 | 폭85cm·5단 서랍장 금액 | **Q09 후속 질문.** 확정한 품목과 규격으로 DB 조회. 폭·단수를 사진에서 추정했다고 주장하지 않음 |

Q04·Q06·Q10은 각각 Q03·Q05·Q09와 묶는 **대화 3쌍**이다. 평가 시 질문 하나씩 독립 호출하면 필요한 맥락이 사라질 수 있다. 현재 앱의 사용자 선택 품목·규격 상태로 전달하거나, 평가 입력에 앞 질문·답변을 명시하는 방식 중 하나를 고정하고 기록한다. 사진을 매 질문마다 반복 전송할 필요는 없다.

이 묶음은 수수료·사진·규격에 집중돼 있다. 배출 절차·요일/시간·공식 신청 링크·제안 거점 오안내·출처 없음의 RAG 평가 전체를 대체하지는 않는다. 기존 계획의 절차·근거 보류 질문은 별도 평가셋으로 유지한다.

## 6. 실제 실행 후 남길 결과

| 열 | 기록 방법 |
|---|---|
| dataset_id / case_id | `yangcheon_v1`과 Q번호. 기존 평가와 구분 |
| run_id / model / version | 실행별 고유값·실제 모델 ID·설정/프롬프트 버전 |
| source_version | 제공본 기준일과 실제 재검수 기준일 |
| context_mode | 독립 질문/선택 품목 전달/연속 대화 중 사용한 방식 |
| status | answered / needs_confirmation / error |
| value_result | 확정 규격의 DB 금액 일치 여부. 해당 없음 별도 |
| source_result | 실제 근거가 응답 내용을 뒷받침하는지 |
| clarification_result | 부족한 규격·구성품·맥락을 확인했는지 |
| decision | PASS / FAIL / REVIEW / NOT_RUN |
| failure_type | 품목오판·규격단정·금액오류·근거불일치·맥락누락·호출오류 |
| duration / usage | 실제 측정값만 기록. 미측정은 미측정 |
| note | 개인정보를 제거한 짧은 분석 |

**집계 원칙**

1. 예시 행, 빈 행, 미실행은 성능 분모에서 제외한다.
2. **Q02는 별도 충돌 확인용으로 분리한다.** 기본 평가 후보는 나머지 9건이며, Q02는 독립 진단 집계로 남긴다. 실행 수·보류·미실행을 기록하고 기본 평가와 합산하지 않는다.
3. 분모는 실제 완료한 평가 케이스 수와 답변·금액·보류 각각의 대상 수를 기록한다.
4. 후보가 나왔다거나 API가 성공했다는 사실을 정답으로 세지 않는다.
5. 보류가 필요한 입력에 적절히 확인 질문한 응답은 성공으로 인정하되, 충분한 근거가 있는 질문을 전부 보류하면 답변 가능성 지표가 떨어지도록 따로 기록한다.
6. 같은 사진으로 여러 질문을 만들었다는 점을 공개한다. 10질문을 독립 사진10장 성능으로 표현하지 않는다.
7. Opik은 비식별 케이스 ID와 점수만 우선 사용한다. 클라이언트의 질문·이미지·원문 응답 자동 수집 여부를 확인한 후 연동한다.

## 7. 다음 액션

1. 분석 담당: 기본 9건의 정답·조건을 검수한다. Q02는 별도 진단 문서를 따른다. Q03 세트/부품 답변 허용 범위와 사진 품목의 독립 정답도 확인한다.
2. PM/분석: 사진 전송 가능한 비식별 작업본·권한 확인. 원본은 비공개 보존.
3. 개발: 후속 질문의 선택 상태 전달과 structured output을 연결. 질문별 출처·날짜 표시.
4. 평가 담당: 동일 조건으로 실제 실행한 뒤 위 표에 결과 기록. 이번 문서만으로 모델 평가 완료로 처리하지 않음.
5. 공유: 원본 대신 검토 보고서·비식별 집계·실패 유형을 Git과 발표 PDF에 사용.

이 평가셋은 규격·후속 질문뿐 아니라 **의도적으로 상충하는 정보에 대한 오류 탐지 능력**을 평가한다. 충돌을 없애지 않고 입력 조건과 채점 규칙을 명확하게 유지한다. 개인정보 처리는 실제 외부 평가 전 별도로 완료한다.

상세 진단 기준: [자료 충돌 탐지 별도 확인](conflict_check.md).
