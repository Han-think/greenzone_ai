## 배운 수준으로 연결할 코드 구성

새 에이전트나 여러 라우터를 만들지 않고 기존 파일을 재사용합니다. 아래는 앞으로 구현할 구성 예시이며 실행 완료 코드가 아닙니다.

| 위치 | 해야 할 일 |
|---|---|
| `guide_service.py` | 기존 검토 완료·지역·시행일 필터와 공식 금액 조회 재사용 |
| `rag_service.py` (추가 예정) | 검증 문서 읽기 → 짧은 문단 분할 → 임베딩 검색 → Gemini 근거 설명. 함수 3~4개로 구성 |
| `service_routes.py` | 기존 APIRouter에 질문 URL 하나 추가. 입력 길이 검사 후 `asyncio.to_thread`로 느린 답변 실행 |
| `templates/disposal.html`, `static/disposal.js` | 기존 화면에 질문 입력·답변·출처 영역만 추가. 새로운 채팅 앱을 만들지 않음 |
| `data/knowledge/` | 이미 있는 문서와 출처 사용. 분석이 검수한 질문/정답 10건 추가 |
| Opik | 평가 케이스ID·근거문서ID·결과 점수 기록. 사용자 주소·검색어·사진 원문 기록 안 함 |

```python
# 추가 예정인 rag_service.py의 처리 순서 예시입니다. 아직 미구현입니다.
def answer_question(question):
    documents = guide.public_documents()  # 기존 검토/시행일 필터를 재사용
    chunks = split_documents(documents)  # 문서를 짧은 근거 문단으로 나눔
    matches = search_documents(question, chunks)  # 배운 LangChain 임베딩 검색
    if not matches:
        return {"answer": "추가 확인이 필요합니다.", "sources": []}
    return generate_answer(question, matches)  # 근거 ID/출처를 함께 반환
```

클래스 상속·에이전트·LangGraph는 이번 완료선에 추가하지 않습니다. 임베딩 모델은 실제 계정에서 사용 가능한 모델을 확인한 뒤 하나만 정하고, API/모델 설정과 예제를 함께 추가합니다.
품목별 규격·금액 질문은 기존 `guide.make_guide`의 확정 ID·수량 계산을 사용합니다. LLM이 금액을 새로 만들지 않습니다. 규격이 없으면 규격을 묻고, 문서가 없거나 시행시점이 불명확하면 보류합니다.

## RAG 응답 약속

```json
{
  "status": "answered",
  "answer": "한국어 안내 또는 추가 확인이 필요합니다.",
  "sources": [{"document_id": "검증된 ID", "title": "근거 제목", "url": "공식 원문", "checked_at": "확인일", "effective_from": null}]
}
```

status는 answered 또는 needs_confirmation으로 구분하고, 보류일 때 sources는 빈 목록으로 반환합니다.
R2가 이 JSON을 먼저 전달하면 R3는 예시 응답으로 화면을 병행할 수 있습니다. 서버는 답변의 문서ID가 실제 검색 결과에 있는지 다시 확인합니다.
관리자가 문서를 바꾸면 검색 인덱스 갱신 방법(관리자 재구축 또는 서버 재시작)을 하나로 정해 안내합니다. 수정된 DB와 오래된 색인을 섞어 쓰지 않습니다.
