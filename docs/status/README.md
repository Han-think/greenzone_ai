# 초기 계획 대비 현재 상태 — 2026-10-26

기준은 GitHub 기본 브랜치 `master`의 최종 통합본이다. [요구사항별 표](requirements_status.csv), [데이터 명세](../../data/DATA_SPECIFICATION.csv), [공개 자료 점검](../review/publication_review.md)을 함께 확인한다. 예전 엑셀의 완료 여부·M/D를 현재 구현률로 사용하지 않는다.

## 판정 방법

초기 요구사항 13건의 문장과 현재 화면·코드를 비교했다. 핵심 흐름이 동작하더라도 자동완성, 규격 신뢰도, 현장 조건 등이 빠져 있으면 부분 구현으로 표시했다. 중요도·분량·제외 항목이 달라 단순 건수 비율을 전체 개발률로 발표하지 않는다. 팀 독립 검수와 다른 PC 재현은 별도다.

## 구현된 현재 마감선

주민은 보유 주소로 담당 생활권·제안 거점을 확인하고, 사진 후보 또는 직접 검색으로 품목·규격·수량을 확인해 공식 배출 안내를 받는다. 관리자는 안내 자료 등록·검토·수정·복원을 수행하고 로그인 후 분석지도와 수거 경로안을 비교한다. RAG는 공식 발췌에 근거한 답변·출처·확인일을 표시한다.

초기 세부 요구사항 중 부분 구현은 안전/접근성 현장검증, 자동완성, 건물별 도로경로 안내, 품목 개수·확률 신뢰도, 위성 전환, 얼굴/번호판 비식별화다. 차량 점유·적치/넘침·영상 이벤트 관제는 이번 범위에서 제외했다. 예약·결제는 공식 사이트 연결만 있고 자체 처리하지 않는다.

## 현재 검증

관리자 임시 DB 검사21건, RAG 핵심 검사9건, 과거 HTTP 계약17건은 기능 계약 검사다. RAG 내용 검토는 개발 고정질문14건의 동일 에이전트 대조이며 보완 후 충족13·부분1이다. 일반 정확도·환각률 또는 팀원 독립 평가로 바꾸어 설명하지 않는다.

## 남은 마무리

1. 팀원이 개발에 쓰지 않은 질문과 실제 시연으로 원문·수치·기능을 독립 확인.
2. 다른 PC에서 `.env`를 각자 설정해 실행 확인.
3. 발표 시간·담당·대표 시연과 제출 형식을 확정.
4. 제출 PDF와 저장소 발표 참조본을 구분한다. PDF 28쪽의 “master 미병합” 문구와 PDF D01–D30/저장소 CSV D01–D18의 목록 차이는 제출본 정리에서 바로잡는다.
5. 공개자료 점검은 키 패턴·메타데이터·로컬 경로를 대상으로 했으며, 전체 개인정보 판정·OCR·재배포 허가 확인을 대신하지 않는다.

## 향후 확장

공식 지정 흡연구역을 별도 시설 목록으로 등록하고 인근 검색을 제공하는 방향이다. 그린존 시설에 흡연구역을 붙이거나 흡연 장소를 새로 지정하는 기능이 아니다. 시설 좌표·운영시간·관리기관·자료 확인일·폐쇄 상태를 검토하고 변경 이력을 관리한다. 현재 양천구의 공식 지정 흡연구역 목록은 확보하지 못했다. [양천구 담배꽁초 쓰레기통 자료](https://www.data.go.kr/data/15104425/fileData.do)는 참고 후보이며 그 위치를 흡연 허용구역으로 표시해서는 안 된다.

추후 공식 예약·수거 상태 연계, 시설 이용 중지 공지, 알림, 재사용·수리 안내를 단계적으로 검토한다. 집 앞 청결과 꽁초 감소는 시범 전후 지표로 확인할 기대 효과이며 현재 관측 성과는 아니다.
