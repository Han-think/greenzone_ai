# 코드·데이터 연결 핸드북

설치·실행은 [프로젝트 README](../README.md), 문서 전체 위치는 [문서 안내](README.md)를 봅니다.
이번 정리는 파일 배치 정리입니다. 새로운 분석·AI 평가를 실행하지 않았습니다.

## 코드 읽는 순서

| 코드 | 역할 |
|---|---|
| `main.py` | 받은 분석 결과 읽기, 검색·지도·분석·경로 API |
| `templates/index.html`, `static/script.js`, `static/map.js` | 검색·후보 탭, 더보기, 지도·마커·검색창 접기 |
| `static/analysis.js`, `folium_report.py` | Leaflet 필터와 Folium 보고 지도 |
| `route_planner.py`, `static/route.js` | 선택 거점의 자동/직접 방문순서 경로안 |
| `service_routes.py`, `static/disposal.js` | 사진·품목·배출 안내·관리자 요청 |
| `guide_service.py` | 공식 품목·규칙과 SQLite 자료·수정 이력 |
| `vision_service.py` | Gemini 공식 품목 후보 → 사용자 확인 |
| `server/rag_service.py` | 검수 문서 검색 → DB 조회 → 답변·출처·보류 |

## 데이터 위치

| 위치 | 용도 |
|---|---|
| `data/greenzone*.geojson` | 팀 웹이 직접 읽는 호환 입력. 중복처럼 보여도 임의 삭제하지 않습니다. |
| `data/received/` | 팀 1·2차 인계 원본과 출처 기록 |
| `data/raw/`, `data/analysis/` | 공식 취득 자료, 이전 수요 분석·배출량 근거와 조건부 추정 |
| `data/processed/` | 웹용 비교 요약·도로 그래프·주소 보완 |
| `data/knowledge/` | 공식 품목·규격·수수료 스냅샷, 검수 문서·법령 발췌 |
| `data/vision/` | 사진 모델 비교 집계·출처/해시. 원본 가구 사진과 구분 |
| `data/local/` | 운영 DB·RAG 색인·비공개 평가·로컬 백업. Git 제외 |
| `greenzone_data_analysis/` | 팀 분석 코드와 재현용 폴더. 웹 입력과 별도 유지 |

현재 공간 기준은 1,585필지·7,193 등록 주거단위·9생활권입니다. 실거주 인구나 실측 폐기물량이 아닙니다.
담당 생활권 195.2m·84.1%와 최근접 가정 172.6m·95.3%를 섞지 않습니다.
등록 도로폭·보호시설 이격은 분석 조건이며 현장 안전·부지 사용승인이 아닙니다.

## 기능을 이어서 수정할 때

1. [현재 구현 현황](status/README.md)과 공유 시트의 범위를 먼저 확인합니다.
2. 데이터 변경은 원본을 보존하고 출처·기준일·연결 ID를 확인합니다.
3. 품목·금액은 DB를 조회합니다. 사진만으로 규격·수량·수수료를 확정하지 않습니다.
4. 관리자는 공식 문서의 검수 상태·확인일·사용기간을 함께 관리합니다.
5. 문서 변경 뒤 RAG 색인이 새 지문으로 갱신되는지 확인합니다. 색인·운영DB를 Git에 넣지 않습니다.
6. 평가할 때 고정 질문 재평가와 독립 평가, Opik 실행 추적을 구분합니다.

## 발표·공유

- 최신 받은 PPT와 교체 SVG는 `docs/presentation/`에 모았습니다.

- 모델 키·관리자 비밀번호·운영 DB·원본 가구 사진은 공유하지 않습니다.
